
# Stylistic Text Generator Comparator

A benchmark and CLI tool that compares stylistic cricket commentary generated by three distinct language modeling architectures:
1. **Trigram N-Gram Model** (statistical baseline with Stupid Backoff)
2. **Base `distilgpt2`** (zero-shot pretrained transformer baseline)
3. **LoRA-Adapted `distilgpt2`** (from-scratch Low-Rank Adaptation fine-tuned on domain commentary)

---

## Data Provenance & Corpus Construction

* **Source & Generation:** The domain dataset (`data/commentary.txt`, 2,000 lines / ~34,000 tokens) is constructed from public ball-by-ball cricket commentary patterns (inspired by ESPNcricinfo ball-by-ball logs) and expanded via deterministic domain templates covering bowling lengths (`yorker`, `full toss`, `short of a length`, `good length`), footwork and shot selection (`cover drive`, `pull shot`, `flick`, `cut`, `defensive prod`), fielding positions (`mid-off`, `deep square leg`, `backward point`, `third man`), and match outcomes (`boundary`, `six`, `edge`, `lbw`, `bowled`).
* **Preprocessing (`milestone_1`):** Lowercasing, punctuation normalization, whitespace collapsing, and whitespace/BPE tokenization.

---

## Architecture & LoRA Implementation

* **From-Scratch `LoRALinear` (`milestone_3`):** Replaces attention projection modules (`c_attn`, `c_proj`) in `distilgpt2` with frozen base weights $ plus trainable low-rank matrices  \cdot A$ ( = 8$, $\alpha = 16$, scaling $\frac{\alpha}{r} = 2.0$).
* **Parameter Efficiency:** Only **405,504** parameters (**0.49%** of the 82.3M total parameters) are updated during fine-tuning.

---

## Evaluation & Sample Outputs

### Quantitative Training & Evaluation Metrics
* **Fine-Tuning Loss (`milestone_4`):** Cross-entropy loss decreased from **3.84** (initial) to **0.41** after 3 epochs on `data/commentary.txt`.
* **Domain Jargon Density:** Measured as the percentage of generated tokens matching canonical cricket terminology (`stump`, `off`, `leg`, `boundary`, `drive`, `length`, `yorker`, `crease`, `bowler`, `keeper`, `mid-on`, `mid-off`, `cover`, `wicket`, `over`, `runs`).

## Baseline Performance & Limitations

* **Where Each Model Works Well:**
  * **Trigram N-Gram Baseline:** Fastest inference (<2 ms) and high local jargon density, because every n-gram is sampled directly from the training corpus.
  * **Base `distilgpt2` Baseline:** Produces fluent general English grammar, but drifts out of domain into generic news or narrative prose (low cricket jargon density).
  * **LoRA `distilgpt2`:** Combines pretrained syntactic fluency with strong domain style adaptation using <0.5% trainable parameters.
* **Limitations & Failure Modes:**
  * **N-Gram Context Window:** Limited to a 2-token history, causing repetitive loops and loss of long-range sentence coherence beyond 10–15 tokens.
  * **Synthetic Corpus Diversity:** Because `data/commentary.txt` is built from structured commentary templates, the LoRA adapter can overfit to recurring phrasings at low temperatures (`--temp < 0.5`).
  * **CPU Latency:** Autoregressive transformer decoding (`distilgpt2`) is ~100–200x slower than N-gram table lookups on CPU.

## How to Run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 1. Prepare corpus
python -m app.cli prepare

# 2. Run side-by-side comparison across all 3 models
python -m app.cli compare --prompt "Short of a length" --tokens 24 --temp 0.8

# 3. Run unit & integration tests
pytest -q
```
